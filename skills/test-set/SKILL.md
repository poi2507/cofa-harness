먼저 무엇을 위한 테스트 셋인지 고른다. 과제에 이미 test 파일이 있으면 그것을 쓰고 새로 나누지 않는다.

## A. 모델 평가용 분할
1. 분할 방식을 데이터로 정하고 근거를 NOTES.md에 쓴다.
   - 시간 컬럼이 있고 미래를 예측하는 문제 → `time`
   - 같은 대상(설비·고객·로트)이 여러 행 → `group` (같은 대상이 학습과 테스트에 섞이면 점수가 부풀려짐)
   - 분류이고 클래스가 불균형 → `stratify`
   - 그 외 → `random`
2. 스크립트로 나눈다(시드 42 고정):
   `python3 scripts/make_split.py data/파일.csv --strategy time --time-col timestamp --target 타깃 [--dedup]`
   → data/splits/train.csv, val.csv, test.csv, split_report.md
3. split_report.md의 자동 점검을 확인한다: 겹침 없음, 합계 일치, 학습-테스트 동일 행 0건, 그룹 섞임 없음, 시간 순서, 각 세트에 모든 클래스 존재.
4. 테스트 세트는 최종 평가에 한 번만 쓴다. 튜닝은 val로만. 전처리(스케일링·인코딩·결측 대체)는 train으로만 fit한다.
5. 테스트가 너무 작으면(양성 10건 미만) 보고하고 교차검증을 함께 제안한다.

## B. LLM 결과 채점용 골든셋
1. 전체에서 20~30건을 뽑는다. 라벨·유형마다 최소 3건, 경계 사례 3~5건 포함. 시드 고정.
2. outputs/golden.csv 열: id, 입력, 사람정답, 비고. 사람정답은 사용자에게 채워 달라고 요청한다(모델이 채우지 않는다).
3. 프롬프트 버전마다 golden.csv로 정확도·오류 유형을 VERIFICATION.md에 기록한다. 골든셋으로 프롬프트를 고친 만큼 과적합 위험을 함께 적는다.

## C. 자동화 파이프라인용 엣지 케이스
tests/fixtures/ 에 작은 CSV를 만든다: 정상 3행 / 빈 파일 / 헤더만 / 필수 컬럼 누락 / 타입 오류 / 키 중복 / 인코딩(cp949) / 날짜 형식 다름.
각 파일마다 기대 결과(통과·경고·실패)를 표로 적고 unittest로 검증한다.

## 공통
- 테스트 셋 파일은 원본과 분리해 저장하고, 만든 명령을 VERIFICATION.md에 남긴다.
- 끝나면 4줄 보고: 했다 / 확인했다 / 확인 못 했다 / 다음.
