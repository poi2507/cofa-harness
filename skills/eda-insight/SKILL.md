목표: "그래프 많이 그리기"가 아니라 **가설 → 검증 → 결론**. 그래프는 결론의 근거로만 남긴다.

## 1. 자동 EDA 리포트 (2분)
```
python3 scripts/eda_report.py data/파일.csv --target 타깃 --time 시간컬럼 --group 그룹컬럼
```
- 긴 형식(timestamp, tag, value)이면: `--pivot timestamp,line --tag-col tag --value-col value`
- 특정 날짜 전후 비교: `--split-date 2026-10-08`
- 결과: `reports/eda.html`(그래프, 브라우저 미리보기로 열기) + `reports/eda_stats.md`(숫자 요약·상관·전후 비교·자동 가설 후보)
- 파일이 여러 개면 조인을 먼저 하고(키는 data_check.md 확인) 합친 파일로 돌린다.
- 스크립트가 못 하는 그래프(산점도, 박스플롯 등)가 필요하면 matplotlib이 있을 때만 추가하고, 없으면 같은 스타일의 inline SVG로 만든다.

## 2. 가설 세우기
eda_stats.md의 "자동 가설 후보"와 과제·메신저의 가설을 합쳐 **3~5개**로 줄인다. 각 가설을 이렇게 쓴다:
`가설 | 맞다면 데이터에서 보여야 할 것 | 틀렸다면 보여야 할 것 | 검증 방법`
메신저·현업이 제시한 가설(예: "습도 탓", "야간조 탓")은 반드시 포함한다.

## 3. 검증 (가설마다)
- **나눠 보기**: 다른 범주·다른 기간·다른 그룹에서도 같은 패턴인가 (심슨의 역설 확인)
- **시점 확인**: 원인 후보의 변화가 결과 변화보다 먼저인가. 변화 시점을 일 단위로 좁힌다
- **대조군**: 같은 기간에 영향을 안 받았어야 할 그룹은 변하지 않았나
- **크기**: 차이·효과크기(d)·표본 수를 같이 쓴다. 표본 30 미만은 "약한 근거"로 표시
- **반례 찾기**: 가설이 맞다면 일어나면 안 되는 일이 데이터에 있는지 찾는다
- 각 검증의 코드와 결과를 VERIFICATION.md에 한 줄씩

## 4. 결론 정리 → reports/insight.md
1. 결론 3줄 (무엇이, 언제부터, 얼마나, 그래서 무엇을 하자)
2. 가설별 판정표: `가설 | 판정(채택/기각/보류) | 핵심 근거 숫자 | 그래프`
3. 핵심 그래프 2~4개만 (eda.html에서 고르거나 새로 그림). 제목에 결론을 쓴다. 예: "L2 라인만 10/8 이후 불량률 2%→7%"
4. 한계: 데이터 품질 문제, 볼 수 없는 변수, 상관과 인과의 거리
5. 다음 확인 사항 (현장에서 확인할 것)

## 하지 않는 것
결론 없는 그래프 나열 · 상관을 원인이라고 단정 · 표본 수 없이 비율 비교 · 현업 가설을 확인 없이 기각 · 한 번 나눠 본 결과로 결론
끝나면 4줄 보고: 했다 / 확인했다 / 확인 못 했다 / 다음.
