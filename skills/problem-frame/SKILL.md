---
name: problem-frame
description: 과제 시작 시, 또는 요구사항이 바뀌었을 때 문제 정의와 REQUIREMENTS.md를 작성·갱신할 때 사용
---
1. 과제 문서·메신저 메시지·데이터 파일 목록을 읽고 REQUIREMENTS.md를 이 순서로 채운다:
   비즈니스 질문 → 분석 질문(측정 가능하게) → 성공 기준·지표 → 제출물 → 제약(시간·환경) → 가정 → 범위 밖 → 질문 목록
2. 요구사항은 체크박스 목록으로 쓰고 각 항목에 필수/개선/여유를 표시한다.
3. 모르는 것은 최대 3개로 압축해 사용자에게 제시한다. 답이 없으면 가정으로 두고 "가정"이라고 표시한다.
4. 유형을 판별한다(원인분석 / 예측·분류 / 이상탐지 / 비정형 LLM / 자동화 / 대시보드). 섞이면 필수 유형 하나만 고른다. PLAYBOOK.md 참고.
5. 계획을 필수/개선/여유 3단계로 제시하고 승인을 기다린다.
