# 유형 프로필: 데이터 처리 자동화 (정제·집계·보고서 생성)
공통 규칙 위에 추가로 따른다. 충돌하면 공통 규칙이 우선.

## 시작 시 추가 질문
- 입력 형식이 매번 같은가(파일명·컬럼·인코딩) / 출력을 받는 사람과 형식 / 실패 시 알림 방식 / 실행 주기

## 필수 산출물 (T+105까지)
1. 입력 스키마 정의 + 검증 함수(컬럼 존재·타입·필수값·중복). 실패 시 명확한 메시지
2. 파이프라인 src/pipeline.py: 읽기 → 검증 → 변환 → 집계 → 출력. **setup.sh가 넣어 둔 뼈대(src/pipeline.py, tests/test_pipeline.py)에서 SCHEMA·KEY·transform·aggregate만 채운다.** 뼈대 테스트 5개가 먼저 통과하는지 확인
3. 출력물: 파일(csv; xlsx 대신 csv) + 요약 텍스트 → outputs/
4. 실행 로그 → logs/run_YYYYMMDD.log: 입력 건수, 출력 건수, 경고, 소요 시간
5. run.sh 한 줄 실행 + 다른 입력(또는 일부 행)으로 두 번째 실행 증명
6. README에 "입력이 바뀌면 고칠 곳" 표

## 규칙
- 경로·날짜·파일명은 인자나 설정 파일로 받는다. 하드코딩 금지.
- 빈 파일, 중복 행, 인코딩 오류, 날짜 형식 불일치를 각각 처리하고 테스트를 1개씩 둔다. 입력 샘플은 `$test-set` C절차로 tests/fixtures/에 만든다.
- 멱등성: 두 번 실행해도 결과가 같아야 한다.
- 외부 전송(메일·API) 기능은 호출 지점만 만들고 실제로 보내지 않는다(규정).

## 검증
- unittest 5개 이상(정상 1, 예외 4). `python3 -m unittest`를 run.sh에 포함한다.
- 입력 건수와 출력 건수의 관계가 설명되는지 확인한다.
