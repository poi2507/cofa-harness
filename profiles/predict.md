# 유형 프로필: 예측·분류
공통 규칙 위에 추가로 따른다. 충돌하면 공통 규칙이 우선.

## 시작 시 추가 질문
- 평가 지표 / 예측 시점(언제까지의 정보를 써도 되는지) / 놓침 vs 오탐 비용 / 운영 시 재학습 가능 여부

## 필수 산출물 (T+105까지)
1. 검증 설계: 분할 방식과 근거, 폴드 수, 학습/검증/테스트 크기 → NOTES.md. `$test-set` + `scripts/make_split.py`(random/stratify/time/group)로 나누고 data/splits/split_report.md의 자동 점검 확인
2. 누수 점검표: 컬럼별 "예측 시점에 알 수 있나" Y/N → reports/leakage.md
3. 베이스라인 점수(상수 → 선형/로지스틱) → 최종 모델 점수. 같은 검증 세트에서
4. 해석: 피처 중요도 또는 계수 상위 10개 + 비즈니스 의미 한 줄씩
5. 오류 분석: 틀린 사례 5건, 패턴, 개선 아이디어
6. 예측 결과 파일 → outputs/predictions.csv + 재현 스크립트

## 규칙
- 지표가 없으면: 불균형 분류 → PR-AUC/F1 + 혼동행렬, 균형 → ROC-AUC/accuracy, 회귀 → MAE(+RMSE). 이유를 기록한다.
- 테스트 세트는 최종 1회만. 튜닝은 검증 세트에서만.
- 시간 분할이면 스케일링·인코딩은 학습 구간으로만 fit한다.
- 불균형이면 "모두 다수 클래스" 베이스라인 점수를 꼭 적는다.
- 모델은 2개까지. 세 번째는 T+150 전에만.

## 검증
- 폴드별 점수와 분산을 적는다. 점수가 너무 좋으면(0.99 이상) 누수부터 의심한다.
- 예측 파일 행 수 = 테스트 행 수, ID 중복 없음.
