# 유형 프로필: 비정형 데이터 LLM 처리 (텍스트·로그·메모)
공통 규칙 위에 추가로 따른다. 충돌하면 공통 규칙이 우선.

## 시작 시 추가 질문
- 라벨 체계가 정해져 있나 / 정답 샘플이 있나 / 호출 한도·비용 / 출력 형식

## 필수 산출물 (T+105까지)
1. 라벨 정의서: 라벨, 정의, 예시 2개, 경계 사례 → reports/labels.md
2. 규칙 베이스라인: 키워드 매칭 분류 + 정확도
3. prompts/v1.md, v2.md … 버전별 샘플 정확도 → VERIFICATION.md
4. 전체 처리 결과 → outputs/labeled.csv + 집계표 + 오류 유형 5건
5. 캐시 파일(outputs/llm_cache.json)과 호출 수·소요 시간 기록

## 규칙
- 키는 os.environ에서만 읽는다. 없으면 멈추고 보고한다.
- 출력은 JSON 스키마를 강제한다. 파싱 실패는 1회 재시도 후 "unparsed"로 기록한다.
- 샘플 검증 먼저: `$test-set` B절차로 골든셋(outputs/golden.csv)을 뽑고, 사용자가 20~30건 정답을 매긴 뒤 시작한다. 정확도 목표를 먼저 정한다(예: 85%).
- temperature 0. 같은 입력은 캐시에서 가져온다.
- 전체 실행 전에 10건 드라이런으로 비용·시간을 추정한다.

## 검증
- 규칙 vs LLM 정확도 비교표. LLM이 더 낫지 않으면 규칙을 채택한다.
- 라벨 분포가 상식과 맞는지 본다(한 라벨이 90% 이상이면 의심).
